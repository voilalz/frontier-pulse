# 每日深读编辑内容模型 v2

## 目标与边界

每天从严格 24 小时内的最多 12 件独立事件中，选择 4～6 件形成一篇有明确主线的文章。候选不足时如实刊发较短文章。正文写今天的变化，引用同一 canonical `eventId` 的此前记录；主题相近的其他事件不得充当历史。保留原有选题政策、原始链接、图片归属与旧版归档阅读。

## 生成流程

1. 程序筛选并去重，得到最多 12 件候选，附上同一 `eventId` 的最多三条此前时间线和原始证据。模型先输出选题提纲：4～6 个新闻 ID、1～3 个主题以及每节的具体问题。没有模型或提纲无效时，程序按证据质量和主题多样性选择 4～6 件，每件单独成节。
2. 程序固定入选 ID 与章节成员。只允许共享可识别主体或项目的事件合章；不满足条件的组合拆成单事件章节。模型再写标题、导语、章节和段落。每段显式引用当期新闻 ID；存在此前记录的事件必须有一段 `change`，把过去和今天的具体动作分开。未提供此前记录的事件不得写 `change`。
3. 写作失败保留标题、摘要和时间线构成的简版，标为 `fallback` 或 `partial`；不能把占位话术伪装成完整文章。模型输出的 ID、URL、图片和证据等级一概不入库。提纲与写作 JSON 分别校验，拒绝新 ID、遗漏、移动事件、脚本与 URL。

## 内容模型

`schemaVersion: 2`。根对象包含 `editionDate`、`generatedAt`、`headline`、`lead`、`chapters`、`events`、`candidateCount`、`eventCount`、`sourceCount`、`generationStatus`、`warnings`、`generationRevision`。`chapters` 有标题、angle、固定 `newsIds` 和 `blocks`；段落块为 `{type: paragraph|change, text, newsIds}`。`events` 是程序生成的引文目录，包含 `newsId`、`eventId`、原题、来源、图片、`evidenceLevel` 和此前的 `history`。四级值为 `primary`、`multi`、`single`、`opinion`：一手仅指事先标记的官方/原发布方，多个转载链接只有独立来源组不少于二组才是多源，观点优先于来源数量。标签是材料类型，不是事实真实度分数。

Web、未来微信公众号正文及邮件都只消费这个内容模型并各自排版。当前交付 Web 适配器和 JSON 契约，不假定公众号账号或外发权限。旧版 `schemaVersion: 1` 归档继续按旧渲染器读取。被编辑政策过滤的事件及引用它的段落全部删除，跨事件标题与导语也清除，避免缓存泄漏。

## 验收

同一输入顺序变化结果稳定；12 候选不等于 12 正文；弱相关内容不合章；历史仅同 `eventId` 且日期早于今天；今日进展与过往区分；四级标签准确处理官方、独立多源、单源与观点；旧归档和新版网页均可阅读；完整离线测试、JS 检查和隔离 fixture 通过。
