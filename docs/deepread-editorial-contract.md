# 每日深读内容契约（修订 13）

新生成稿使用 `schemaVersion: 2`、`generationRevision: 13`，北京时间按日发布。入口仍为 `build_daily_deepread`，旧版本生成和解析保留给历史兼容及既有回归。生成不获取新网页，只使用新闻流程已经捕获的证据与日期归档。

## 主题与深度

候选池最多 12 件，正文最多 6 件事件、1–3 个主题。一个主篇目标 800–1500 汉字，最多两个短篇各 300–500 汉字；全文目标 1500–3000 汉字。材料不足时保留简版，不补写无依据的背景或重复事实凑篇幅。

主题按具体问题组织，允许同项目或共享明确技术问题的 2–3 件新闻组成一章。大类、同机构或泛泛的科技相似性不能作为合并理由。事实之后解释具体方法、机制、实验条件或工程约束，最后明确适用边界及待验证的问题。独立校对同时判断整章是否仍逐条罗列、重复事实或缺少实质分析；事实逐句合格但整章浅薄，仍须重写。

评论、周报、活动、纪念、招生、奖学金、犯罪、政治政策、图片说明及缺少技术进展的常规演训不入选。不同新闻 ID 的相同主体与行动、相近标题或相同金额报道先聚类；不同产品、金额或动作阶段不能误合并。独立来源组而非链接数量决定多源等级，一手来源只作同等重要度的排序依据。有材料时保留 AI／前沿技术候选，并预留无人、航空航天候选。

每类至多一个主题；3 篇时最高占比为 1/3。1–2 篇不能严格满足 40% 上限，材料稀疏例外记在 `qualityMetrics.categoryBalanceException`。

## 事实、分析与证据

`chapters[].blocks[]` 包含 `type`、`newsIds`、`sentences` 与由各句原样拼接的 `text`。事实类型为 `paragraph`（当期事实）、`background`（历史背景）、`change`（历史与当期变化）；分析类型为 `analysis`、`comparison`、`watch`，页面标为编辑分析。`observations` 保持空数组，后续问题放在主题正文内。

每个 `sentences[]` 为 `{text, evidenceIds, semanticCheck}`，绑定 1–3 个实际证据 ID。数字单位、否定、范围、仿真条件、计划与说话主体先做规则检查，再独立调用校对模型；仅 `supported` 可公开，`partial`、`unsupported` 或校对缺项均拒绝。原发布方材料保留归属。分析不能增加无依据的数字、引语、实体事实、确定因果，也不能把未披露写成已证明不存在。

标题、主题角度、文章标题和导语作为编辑表达独立校对，不再要求是英文原句子串。`semanticCheck` 的 SHA-256 绑定角色、文字、引用顺序、证据正文和 URL；`editorialCheck` 绑定主题标题、角度、成员及段落顺序。改变文字、引用或章节组织后必须重新校对。服务端及浏览器都验证绑定。绑定证明校对对象未变化，不证明模型一定判断正确。

`events[]` 是实际捕获的来源目录：`newsId`、`eventId`、原文标题、抽取摘要、证据、来源、图片、证据等级及项目键。中文简讯只使用仍有来源绑定的中文标题／有效译名，标题、来源链接与事件目录必须一致。正文与简讯事件不重复。

## 历史关联

归档正文证据进入 `events[].history[]`，携带日期、来源、证据及此前 `watchFor`。仅精确项目／型号或同一事件匹配可进入历史，最多三条；历史日期必须早于当期。紧凑搜索记录缺少正文证据时不承担事实依据。

写作输入实际传入 `previousSameEvent`、`previousProject`、`previousWatchFor`。`paragraph` 不能使用历史证据；`change` 必须同时引用历史和当期证据。缺少已捕获历史时不编背景。通过校验的 `watch` 保存到日期稿，供后续同项目输入核对。

## 发布与恢复

| `readerStatus` | 内容与门控 |
| --- | --- |
| `complete` | 所有正文合格，全文及主篇达到目标，无待恢复简讯 |
| `partial` | 至少一篇合格主题；每篇至少 300 汉字、两条当前事实对应两个不同证据记录、一段有内容的分析、三个段落；其他主题失败或总篇幅不足 |
| `brief` | 正文全部失败，只发布当日来源绑定的中文标题与原报道链接 |
| `retained` | 当日没有合格主题，可沿用完整旧稿最多一天；固定显示未更新与原内容日期 |
| `unavailable` | 无合格正文、简讯或一天内可沿用的旧稿，显式记录深读失败 |

合格章不能因其他章失败而被清空。同日恢复失败仍保留已发布的合格简版。深读状态与日报分开；简版、简讯及沿用为 `degraded`，无合格内容为 `failed`，不会导致健康日报重新选稿。

每章最多一次定向修复，反馈具体句号与失败规则。总生成预算默认 480 秒（可配置 30–600 秒），单调用最多 90 秒且不叠加 HTTP 重试；预算耗尽保留此前合格主题。公开诊断不记录 provider 异常正文。

`topicPlan` 与 `generationInputs` 保存首次选题和来源快照；后者包括未公开的失败主题来源，用于恢复，不作为网页内容展示。恢复使用正式日报初始快照和原始选材时间，复用已校验正文，仅重试缺章。所有计划主题已合格但篇幅不足时保持简版并停止重复生成。

保留每日 08:00 的既有安排；新增北京时间 08:30、09:00、09:45 深读恢复，日报完成后亦可触发。发布仍经 `publication.validate_publication`、不可变快照及原子事务；独立开发分支不能写生产数据。

## 阅读与归档

句末小号引用跳到章末统一证据目录，并自动展开。正文区只使用一张主图，其余章末资料用缩略图。简版、简讯、沿用状态在标题附近持续说明，当前发布日期与旧稿内容日期分开，日期选择不会把沿用稿误当当天新稿。

历史日期保留发布时格式，提示历史简版。早期缺少证据快照的归档按其原契约读取；具有快照的旧稿仍检查哈希和绑定，损坏数据不能通过兼容路径。旧版归档可读不等同于现行完整版合格，也不能绕过一天沿用门槛。
